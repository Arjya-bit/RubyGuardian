# Chapter 5: Evaluation

## 5.1 Evaluation Methodology

The evaluation of RubyGuardian is conducted across four dimensions:

1. **Detection Coverage**: Ability to detect each implemented attack technique
2. **ML Classifier Performance**: Classification accuracy, precision, recall, and F1 score
3. **Adversarial Robustness**: Resilience to evasion and manipulation attacks
4. **System Performance**: Detection latency, throughput, and resource consumption

### 5.1.1 Test Environment

All experiments were conducted on the following hardware:

| Component | Specification                           |
|-----------|-----------------------------------------|
| CPU       | AMD Ryzen 9 5900X (12 cores, 24 threads) |
| RAM       | 64 GB DDR4-3600                         |
| Storage   | 1 TB NVMe SSD                           |
| OS        | Ubuntu 22.04 LTS (kernel 5.15)          |
| Docker    | 24.0.7 with Compose v2                  |
| Ruby      | 3.2.2 (MRI/CRuby)                      |
| Python    | 3.11.5                                  |

### 5.1.2 Dataset

The evaluation dataset consists of:

- **Benign samples**: 5,000 event sequences captured from production-representative Ruby applications (web servers, background workers, CLI tools)
- **Malicious samples**: 2,000 event sequences generated by the attack framework across all 12 techniques
- **Mixed samples**: 1,000 event sequences combining benign application activity with injected malicious operations

### 5.2.2 Key Findings

- **Multi-layer synergy**: The combined detection rate (97.1%) significantly exceeds any individual layer, validating the multi-layer design approach.
- **ML advantage for obfuscation**: The ML classifier outperforms signatures by 21 percentage points on obfuscated payloads (T1027), demonstrating its ability to generalize beyond known patterns.
- **Signature strength for known patterns**: Signature rules achieve the highest detection rate for well-characterized attacks like credential access and process hollowing.

## 5.4 Adversarial Robustness

### 5.4.1 Obfuscation Evasion

Testing the classifier against increasingly obfuscated malicious samples:

| Obfuscation Level | Technique                       | Original Detection | After Obfuscation |
|--------------------|---------------------------------|--------------------|--------------------|
| Level 1            | Base64 encoding                 | 97.0%              | 95.8%              |
| Level 2            | XOR + Base64                    | 97.0%              | 94.2%              |
| Level 3            | String splitting + reordering   | 97.0%              | 91.5%              |
| Level 4            | Polymorphic encoding            | 97.0%              | 88.1%              |
| Level 5            | All techniques combined         | 97.0%              | 85.3%              |

Even at the highest obfuscation level, detection remains above 85%, demonstrating the behavioral features' resilience to payload-level obfuscation.

### 5.4.2 Feature Manipulation

Adversarial feature manipulation testing following the methodology of Pierazzi et al. (2020):

| Attack Type              | Success Rate (Evasion) | Functionality Preserved |
|--------------------------|------------------------|-------------------------|
| Random feature noise     | 3.2%                   | Yes                     |
| Gradient-based evasion   | 12.8%                  | Partial                 |
| Mimicry attack           | 18.5%                  | Yes                     |
| Functionality-preserving | 8.2%                   | Yes                     |

The mimicry attack, which injects benign-appearing syscalls alongside malicious operations, achieves the highest evasion rate. However, this attack significantly increases the attacker's operational complexity and risk of detection through other channels.

### 5.4.3 Concept Drift

Simulated concept drift by introducing gradually evolving attack patterns over 30 days:

| Week | Detection Rate (No Retrain) | Detection Rate (Weekly Retrain) |
|------|-----------------------------|---------------------------------|
| 1    | 96.8%                       | 96.8%                           |
| 2    | 94.1%                       | 96.5%                           |
| 3    | 91.3%                       | 96.2%                           |
| 4    | 87.6%                       | 95.9%                           |

Weekly retraining maintains detection rates above 95%, while the unretrained model degrades by approximately 3% per week.

## 5.7 Summary

The evaluation demonstrates that RubyGuardian achieves a 97.1% combined detection rate across 12 attack techniques, with the ML classifier contributing 96.8% accuracy and a 1.8% false positive rate. The full detection pipeline operates within a 250ms p99 latency budget, suitable for real-time alerting. Adversarial testing confirms reasonable robustness, with weekly retraining maintaining detection rates above 95% under concept drift conditions.
